# 운반 모델의 학습과 배포 검증

데이터 생성과 VLM/VLA 파인튜닝은 조교의 **로컬 GPU**에서 진행합니다.
Colab에서는 공개 배포 파일 다운로드, 무결성 확인, GPU 추론만 검사합니다.

## 무엇을 성공으로 세는가

`scripts/evaluate_motor_skill.py`는 지정한 숫자 큐브를 실제로 집어 올리고,
공중에서 운반한 뒤 올바른 구역에 안정적으로 놓았는지 검사합니다.
지시하지 않은 물체를 집거나 다른 정답 물체를 훼손하면 엄격 성공에서 제외합니다.
처음부터 정돈돼 있던 다른 아홉 물체는 운반 성공으로 세지 않습니다.

- `single`: 방해물 없는 단일 운반입니다. 숫자로 여러 후보 중 하나를 고르는 능력을 입증하지 않습니다.
- `selection`: 여러 미정리 큐브 중 지시한 하나만 운반합니다. 단일 운반과 따로 보고합니다.
- `--full-horizon`: 중간에 한 번 성공해도 실행을 계속하여 이후 재파지나 실패 역전을 확인합니다.

모델과 캐시 길이 선택에는 `validation`만 사용합니다. 모델/설정을 고정한 뒤
별도 `sft_test`를 한 번 평가합니다. 이것은 A~E의 최종 mixed benchmark와 별도입니다.
이 진단은 가속 시뮬레이션이므로 A~E 제한 시간 실험의 속도로 해석하지 않습니다.
씬 단위 ACC/F1과 함께 실제 운반 성공 수, 시행 수, 신뢰구간을 확인하세요.

## 학습 가중치의 정밀도

Transformers가 모델의 일부를 BF16으로 구성할 수 있어, 설정 하나만으로는
FP32 학습 가중치가 보장되지 않았습니다. 현재 `train_vla.py`는
`vlapipe/model_loading.py`의 프로세스 내부 factory를 사용해 가중치를 읽기 전에
학습 파라미터를 FP32로 만듭니다. `--mixed-precision bf16`은 연산 정밀도에 적용됩니다.
추론은 저장된 각 텐서의 정밀도를 복원합니다. backbone 전체를 임의의 한 정밀도로
바꾸지 않습니다. 설치된 LeRobot/Transformers 소스는 이 기능을 위해 수정하지 않습니다.

VLM/VLA 학습기는 같은 checkout의 학습 잠금을 공유합니다. 다른 학습이 진행 중이면
기본적으로 중단하고, `--wait-for-gpu`를 주면 기다립니다.
큰 VLM 학습과 `evaluate_motor_skill.py`는 추가 GPU 잠금을 공유합니다.
VLM의 긴 이미지·텍스트 배치와 운반 평가가 겹쳐 GPU 메모리가 부족해지는 것을 방지합니다.
일반 학생 실행기의 추론은 이 잠금의 대상이 아닙니다.

`train_vla.py --expert-only`는 기반 이미지·언어 모델을 명시적으로 고정하고 행동 생성부를 학습합니다.
이전에 backbone도 학습한 체크포인트를 불러와도 고정 설정이 적용됩니다.
`--chunk-size`는 한 번에 예측할 미래 행동 수, `--policy-action-steps`는 다시 관측하기 전 실행할 행동 수입니다.
이는 실행기의 부분 작업 예산(`action_steps`, 예:240스텝)과 별개입니다.
캐시 실행 수는 예측 행동 수 이하여야 합니다. 설정은 학습 기록과 체크포인트에 남습니다.

### 선택적 로컬 학습 가속

`train_vla.py --expert-only --vision-cache <캐시 폴더>`는 학습 내내 고정된
이미지 인코더의 실제 RGB 특징을 한 번 계산하여 재사용합니다. 물체 정답이나 위치를
추가하지 않으며, 언어와 행동 생성은 기존 SmolVLA 경로로 학습합니다.
이미지 데이터셋, augmentation 비활성, `num_workers=0`인 학습만 지원합니다.
고정된 인코더·입력 데이터·계산 정밀도가 달라지면 별도 캐시를 생성하고 해시를 검사합니다.
캐시 생성에는 저장 공간이 필요합니다. 모델 배포에는 캐시를 포함하지 않습니다.

이 옵션은 기본적으로 꺼져 있습니다. 사용 전 실제 GPU에서 원래 학습과의
loss/gradient 일치 및 저장 모델의 일반 RGB 추론 재로딩을 확인해야 합니다.
내보낸 모델의 입력은 RGB 두 카메라와 state16, 출력은 action7로 동일합니다.
단순 학습 가속이며 성공률을 보장하는 기능은 아닙니다.

`finetune_planner.py --freeze-vision`은 상위 VLM의 이미지 인코더를 고정하는
별도 옵션입니다. VLA의 이미지 캐시 옵션과 구분하세요. 상위 VLM도 학습 파라미터는
FP32로 유지하고, `--autocast-bf16`은 GPU 연산에만 적용합니다.

## 행동 타깃 실험

기본 타깃은 기존 `delta`입니다. 학습 데이터 준비 시 선택할 수 있는
`--action-representation absolute_position`은 신경망의 XYZ 출력만 다음 **로봇 제어 목표 위치**로
학습합니다. 실행 직전에 현재 로봇 제어 목표와의 차이를 기존 delta7 명령으로 바꿉니다.
물체 정답 위치를 추론 입력에 넣거나 규칙 제어기로 행동을 대체하지 않습니다.
RGB 두 카메라, state16, 외부 action7 및 기존 제어기 수치는 유지합니다.

이 모델은 `action_representation.json`이 필요합니다. 제공 실행기는 이를 자동 적용합니다.
직접 실행 루프를 작성하면 매 행동 전에 다음 연결을 넣으세요.

```python
policy.set_controller_target(env.ctrl.target_pos)
action = policy.select_action({**env.get_obs(), 'task': instruction})
env.step(action)
```

이는 로봇 actuator의 명령 상태이며 물체 인식 결과가 아닙니다. 원시 시연 파일은 바꾸지 않습니다.
서로 다른 행동 타깃으로 학습한 A와 B/C는 공정한 비교군으로 바로 묶지 않습니다.
A는 같은 원본 시연에 전체 과제 라벨을 붙여 별도로 학습하고, B/C는 부분 지시문 모델을 공유합니다.

## 번호 지시를 따르는지 별도로 확인하기

운반 성공률과 번호 선택 정확도를 구분하세요. 같은 목적지로 가는 큐브 세 개를 놓고,
물리 상태와 로봇 시작 상태를 그대로 유지한 채 지시하는 번호만 바꾸면
목적지나 위치만 외워서 성공하는 경우를 확인할 수 있습니다. 이 검사는 부분 지시를 받는
B/C 공통 VLA에 적용합니다. 전체 정리를 지시하는 A의 평가 기준으로 그대로 사용하지 않습니다.

이런 짝 비교에서는 `evaluate_motor_skill.py --policy-seed 42`로 각 실행의
정책 난수도 동일하게 고정할 수 있습니다. 각 결과에는 실제 `policy_seed`가 기록됩니다.
옵션을 생략하면 기존처럼 사례 순서에 따라 `42 + case_index`를 사용합니다.
같은 배치에서 번호만 바꾼 세 실행은 독립 씬 세 개가 아닙니다.
독립 배치 개수를 함께 보고하고, 신뢰 구간은 배치 단위 재표집으로 계산하세요.
기본 출력의 사례별 Wilson 구간을 이 짝 비교의 독립 표본 신뢰 구간으로 해석하지 않습니다.

`models/release_manifest.json`의 측정 범위와 `validated_motor_policy`를 먼저 확인하세요.
`models-preview-20261106-r1`은 운반 성공률 0/10이었던 연결 점검용 프리뷰입니다.
코드의 연결 검사 통과나 학습 loss 감소만으로 정상 운반 모델이라고 부르지 않습니다.
새 버전은 다른 immutable Release에 배포하며, 기존 모델은 자동으로 덮어쓰지 않습니다.
새 폴더에 설치하려면 `download_models.py --models-dir <새 경로>`를 사용하고
노트북의 모델 폴더도 같은 경로로 지정하세요.
기본 `models/` 경로를 유지하며 새 버전을 받으려면 `download_models.py --upgrade`를 사용하세요.
새 번들 검증이 끝난 뒤 기존 모델을 `models/_previous/`에 백업하고 교체합니다.

### 현재 기본 VLM R5: 공개 파일의 Colab GPU 비교 (2026-11-06)

상위 VLM은 R5를 기본 배포 모델로 선택했습니다. 학습은 로컬 RTX3090Ti에서 진행했고,
공개 ZIP 다운로드·SHA256 검사·추론은 실제 Colab RTX PRO6000에서 확인했습니다.
T4 검증 결과는 아닙니다. 세 모델 모두 같은 이미지와 프롬프트를 받았습니다.

| 같은 계획 입력132개 | R2 | R3 | R5 |
|---|---:|---:|---:|
| 목표 물체·목적지 쌍 F1 | .6053 | .8099 | **.9259** |
| 응답 형식 준수 | 100/132 | 130/132 | **131/132** |
| 교사와 순서까지 일치 | .4167 | .5682 | **.6364** |
| 별도 실제 B/C 프롬프트4개: 목표쌍+done 정답 | 0/4 | 2/4 | **4/4** |

R5는 기존92개 입력의 F1이.9532, 새 초기40개는.8632입니다. 초기10물체20개에서는
F1.9474였지만 교사의 작업 순서까지 같았던 경우는0/20이므로 두 지표를 구분하세요.
`balanced_initial_validation_250018`에서는 없는 `object_11`을 제시했습니다.
자동 교정하지 않고 스키마 실패로 점수에 반영했으며 원본 응답도 공개했습니다.

이 입력에는 같은 씬의 여러 진행 단계가 포함됩니다. 독립 씬132개나 로봇 운반 성공률로
해석하지 않습니다. VLA의 운반·번호 선택 검증 및 A/B 학습 조건은 별도입니다.
기본 `vla_hier`는 여전히 미검증 운반 프리뷰R2이며, A도 기존 디버깅 모델입니다.

```powershell
python scripts/download_models.py --roles vlm --upgrade
```

기존 로컬 VLM은 이 명령으로 명시적으로 갱신하기 전까지 유지됩니다.
이전 모델은 `models/_previous/`에 보관합니다. 비교용 R2/R3는 각각
`models/release_manifest_planner_r2.json`, `models/release_manifest_planner_r3.json`으로
선택할 수 있으며, 모든 선택에서 B/C 운반 모델은 동일합니다.
[R5 모델·검증 입력](https://github.com/semin126/VLA2026/releases/tag/models-planner-20261106-r5),
[세 모델의 원본 응답·점수](https://github.com/semin126/VLA2026/releases/download/models-planner-20261106-r5/planner_r5_colab_matched132_evidence.zip)를 확인하세요.

**실제 학생 실행기 연결도 별도로 검사했습니다.** 같은 공개R5와 기존 운반R2로,
이미 사용했던 한 큐브 validation 씬에서 B와 기본 C(`action_steps=240`)는 모두 완료했습니다.
각각 VLM을 한 번만 호출했으므로 C 피드백 루프의 우수성을 보인 결과는 아닙니다.

반면 재계획 경로를 검사하려고 작업을60스텝으로 끊은 C는 실패했습니다.
첫 `object_2` 운반이 끝나기 전에 재계획하여 `object_6`을 잘못 선택했고,
다음 재계획에서 빈 계획을 반환해 종료했습니다. 실제 동작 중인 이미지에 대한
재계획이 항상 정확하다고 가정하지 마세요. 계획 로그는 실행 후에도 보존되며
메모리의 `report.events`와 디스크의 `events.jsonl`이 일치하는 것도 확인했습니다.
[성공·실패 보고서와 실행 코드](https://github.com/semin126/VLA2026/releases/download/models-planner-20261106-r5/planner_r5_colab_student_pipeline_evidence.zip)를 함께 공개했습니다.
이 세 실행은 한 씬의 연결 진단이며 독립 성공률이나 동일 예산 B/C 비교가 아닙니다.

### 이전 VLM R3 비교 기록 (2026-11-06)

모든 추가 학습은 로컬 RTX3090Ti에서 진행했습니다. 공개 R3 ZIP을 실제 Colab
RTX PRO6000 약96GB에서 내려받아 해시를 확인한 후 추론했습니다. T4 검증은 아닙니다.

| 같은 52개 이미지·프롬프트 | R2 | R3 |
|---|---:|---:|
| JSON 형식 | 43/52 | 52/52 |
| 계획 pair F1 | 0.7481 | 0.8996 |
| 계획 전체 일치율 | 63.46% | 69.23% |

R3의 확장 validation92개에서는 JSON92/92, pair F1 .9114입니다.
이92개는 이전52개와 구성 비율이 다르므로 두 세트 점수로 개선율을 계산하지 않습니다.
같은 씬의 여러 문맥이 포함된 자동 생성 라벨이며, 로봇 운반 성공률이 아닙니다.

학생 `valid_open` 초기 프롬프트에서는 R2가10개 중6개(F1 .75), R3가4개(F1 .5714)를
제안했습니다. 두 모델 모두 불필요한 추가 대상은 없었지만 누락이 남았습니다.
당시에는 이 실사용 회귀 때문에 기본 manifest를 R2로 유지했습니다. 현재 기본은 위 R5입니다. R3는
`--manifest models/release_manifest_planner_r3.json --roles vlm --upgrade`로 명시적으로 선택하세요.
B/C에서 같은 버전을 사용하고 실제 선택 기록을 남겨야 합니다.
[R3 배포와 원본 응답](https://github.com/semin126/VLA2026/releases/tag/models-planner-20261106-r3)을 확인할 수 있습니다.

대상 개수·번호·배치를 바꿔 로컬에서 만든 별도 초기 씬40개도 동일 Colab GPU에서 비교했습니다.
이 세트에는 완료 문맥이 없고, 20개는 정리 대상10개, 나머지20개는1~9개입니다.

| 새로운 초기 씬40개 | R2 | R3 |
|---|---:|---:|
| JSON 형식 | 27/40 | 38/40 |
| 계획 pair F1 | 0.4297 | 0.5765 |
| 대상10개인20씬의 완전한 계획 | 0/20 | 0/20 |

R3가 이 세트의 평균은 더 높지만 두 모델 모두 새 배치에서 대상 누락이 남습니다.
학생 시작 씬 하나의 결과와 이40개 평균을 구분하세요. 이 비교의 R2와 R3 모두 프리뷰입니다.
기존52/92개와 이40개의 구성이 달라, 서로의 점수 차이를 모델 개선율로 해석하지 않습니다.
이40개는 독립 검증용 기하 교사 라벨이며 모델 학습이나 최종 mixed benchmark에 사용하지 않았습니다.
[원본80개 응답과 결과](https://github.com/semin126/VLA2026/releases/download/models-planner-20261106-r3/balanced_initial_comparison_evidence.zip)도 공개했습니다.

## 부분 운반 프리뷰 R2: 로컬·Colab 실추론

[motor preview r2](https://github.com/semin126/VLA2026/releases/tag/models-motor-preview-20261106-r2)는
B/C가 공유하는 부분 지시 모델입니다. 같은 고정 단일 운반10씬을 각240스텝 끝까지 실행해
로컬 RTX3090Ti에서4/10, 실제 Colab RTX PRO6000에서5/10 최종 안정 운반에 성공했습니다.
같은 모델·씬의 하드웨어 반복 검증이므로 독립20개 표본이나 학습 향상으로 합치지 않습니다.
Colab 성공률의 사례별 Wilson95% 구간은23.7~76.3%로 넓습니다. 60% 합격 모델은 아닙니다.

로컬에서는 한 번 성공한 사례6개 중2개가 이후 다시 흐트러져 최종 성공에서 제외됐습니다.
처음부터 다른9개 물체가 맞게 놓여 있는 조건이므로, 전체 씬ACC90%를 모델의 운반 정확도로
보고하지 않습니다. 이 검사는 여러 큐브 중 번호 선택이나 전체10개 정리를 검증하지 않습니다.

번호 선택도 별도로 검사했습니다. 같은 목적지로 가는 큐브 세 개의 frozen 배치10개에서 지시 번호만 바꾼30회 Colab GPU 추론의 엄격 성공은 **3/30(10%)**였습니다. 같은 배치의 세 실행은 서로 연관되므로 독립 표본 수는10개이며, 배치 단위 부트스트랩95% 구간은0~20%입니다. 세 지시를 모두 성공한 배치는0/10입니다. 단일 운반5/10과 합쳐 평균을 내지 않습니다. [판정30개와 실행 코드](https://github.com/semin126/VLA2026/releases/download/models-motor-preview-20261106-r2/motor_preview_r2_selection_colab_evidence.zip)로 확인할 수 있습니다.

3k 스냅샷은1k/2k/3k/4k의 검증3/10,2/10,4/10,3/10을 보고 선택했습니다.
선택 편향이 있을 수 있고 최종 봉인 씬은 사용하지 않았습니다.
A는 여전히 다른 학습 조건의r1 모델이므로 이 조합으로 A/B 연구 효과를 해석하지 않습니다.
B/C 모두 같은vla_hier를 쓰며 VLM R2/R3/R5 선택과 독립적으로 같은 모터 버전을 설치합니다.

공개 ZIP의 SHA256과 내부 파일 해시를 확인한 뒤 Colab에서 실제 CUDA 추론했습니다.
추론·평가48.28초, peak allocated 약1.89GB였으나, 다른GPU·실행 부하의 시간 비교가 아닙니다.
T4 검증은 하지 않았습니다. 모든 학습과 학습용 데이터 생성은 로컬에서 수행했습니다.
Release의 Colab 증거에는10개 씬별 판정과 실행 코드가 있으며, 전체 스텝 행동 기록은 없습니다.

기존 단일 운반 시연100개 중99개는 물체를 놓은 뒤 그리퍼가 아직 낮은 위치에 있을 때 기록이
끝났습니다. 놓기 성공 라벨이 틀렸다는 뜻은 아니지만, 완료 후 후퇴·유지 동작의 학습 범위가
부족합니다. 해당 원본은 보존하며 교사 후퇴와 실제 물리50스텝 유지 시연, 같은 씬에서 목표 번호를 바꾼 시연을 별도로 수집했습니다. 개선 후보 모델의 성능은 별도로 검증하고 있습니다.

## Windows에서 많은 시연 폴더를 변환할 때

`prepare-actions`는 검증한 입력 폴더 목록을 출력 폴더 옆의 `*_input_dirs.json`에 남기고
변환기에 파일로 전달합니다. 수백 개의 긴 경로 때문에 Windows 명령줄 한도를 넘는 오류를
피하면서, 같은 원본·학습/검증 분리를 유지합니다. 기존 `--input-dir`도 계속 지원합니다.
직접 실행할 때는 `prepare_vla_training.py --input-dirs-file inputs.json`을 쓸 수 있습니다.
파일은 UTF-8 JSON 문자열 배열이며 상대 경로는 그 파일이 있는 폴더를 기준으로 해석합니다.
